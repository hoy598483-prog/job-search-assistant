# 交付、协作与迭代

## 原型层级

| 层级 | 目的 | 常见形式 |
| --- | --- | --- |
| 概念原型 | 验证用户是否理解价值 | 流程图、文案、可点击稿 |
| 行为原型 | 验证用户能否完成任务 | 手动服务、低代码工作流、模拟数据 |
| 技术原型 | 验证实现约束 | API 调用、数据管道、最小代码 |
| 可用版本 | 验证持续使用和运营 | 有状态、监控、异常处理的产品 |

不要把演示成功等同于可用版本；也不要在概念尚未验证时过早建设复杂基础设施。

## 与研发协作

产品经理需要让团队明确：问题、目标、用户流程、优先级、验收标准、数据与权限约束、未知风险。研发负责实现方案、技术拆解和工程质量；双方共同讨论取舍。

好协作不是把 PRD 扔给研发，而是在不确定项上尽早对齐：数据是否存在、延迟是否可接受、模型成本、失败模式、隐私和权限、上线监控。

## 发布前检查

- 核心流程是否可完成；
- 错误和空结果是否有解释；
- 用户输入是否被正确处理；
- 权限与敏感资料是否遵循最小必要原则；
- 指标、日志和反馈渠道是否准备；
- 是否有回滚或降级方案。

## 迭代节奏

每轮迭代只选择一个最重要问题：观察证据 → 定义假设 → 修改 → 测试 → 记录结果 → 决定扩大、修正或停止。持续积累失败案例，避免相同问题反复出现。
