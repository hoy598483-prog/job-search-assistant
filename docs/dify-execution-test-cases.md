# 求职训练计划执行 Agent：测试资料

在 Dify 预览页逐条发送以下内容。每个案例建议使用一个新会话，避免前一个案例的 `weekly_plan` 影响结果。

## P01：AI 产品经理｜正常创建计划

```text
目标岗位：AI 产品经理，偏企业协同和知识管理场景
背景：数学硕士；Python 基础；暂无正式工作、实习和个人项目；理解基础产品设计流程
正在投递的岗位要求：理解大模型、RAG、Agent；能从 0 到 1 完成概念验证、用户验证和迭代；能协同产品、研发和设计；有企业级 AI 产品或智能体项目更好
项目主题：求职准备 Agent
每日时间：120 分钟
```

期望结果：生成 7 天计划；每天都有目标、步骤、交付物和验收方式；第 1 天围绕 JD 能力地图或项目边界展开。

## P02：量化研究｜正常创建计划

```text
目标岗位：量化研究员，偏 A 股小市值因子研究
背景：数学硕士；有 Python 基础；熟悉基础概率统计、线性代数；没有量化实习和实盘经验
正在投递的岗位要求：熟练 Python、Pandas、NumPy；具备概率统计、回归分析和时间序列基础；能完成数据清洗、因子构建、回测和研究报告；理解风险和过拟合问题
项目主题：A 股小市值因子研究与回测报告
每日时间：120 分钟
```

期望结果：计划聚焦数据、因子假设、回测、风险检查和研究报告；不能承诺收益或给出投资建议。

## P03：外贸业务｜正常创建计划

```text
目标岗位：外贸业务员，偏消费品出口
背景：数学硕士；英语读写尚可；无外贸经验；会使用 Excel 和基础 Python
正在投递的岗位要求：英语邮件沟通；理解询盘、报价、打样、订单和交付流程；有客户开发意识；能整理产品资料和市场信息
项目主题：模拟完成一个消费品海外客户开发与报价方案
每日时间：90 分钟
```

期望结果：计划包含目标市场调研、客户画像、英文开发信、报价逻辑和复盘；不应虚构真实客户或真实成交。

## E01：通过第 1 天

先用 P01 创建计划，查看第 1 天任务后发送：

```text
我完成了第 1 天任务。
交付物：AI 产品经理岗位能力地图。
我整理了 3 份 JD，共提取 9 条原文要求，分为产品能力、AI 技术理解、交付协作三类；每项能力均标注了“已有、待补足或待验证”。
文件内容如下：
- 产品能力：从 0 到 1 验证、用户访谈、需求拆解（3 条 JD 原文）
- AI 技术：大模型、RAG、Agent、知识库（4 条 JD 原文）
- 交付协作：原型、研发协作、产品迭代（2 条 JD 原文）
- 待补足：没有真实项目证据，因此选择构建求职准备 Agent 作为作品集。
```

期望结果：评审引用当天验收标准；若判定通过，`current_day` 从 1 变为 2，再问“今天做什么”时展示第 2 天。

## E02：未通过第 1 天

先用 P01 创建计划，查看第 1 天任务后发送：

```text
我看了几份 AI 产品经理招聘要求，感觉它们都要求 RAG 和 Agent。我暂时还没有整理文档，明天再做。
```

期望结果：判定为 `revise`；`current_day` 保持为 1；返回一个可在 30–60 分钟完成的补交动作，不能直接推进到第 2 天。

## E03：用户只询问当前任务

先用任一案例创建计划，然后发送：

```text
今天做什么？
```

期望结果：只展示 `weekly_plan.current_day` 对应的一天，不列出整周，也不重新生成计划。

## E04：模糊完成声明

先用任一案例创建计划，然后发送：

```text
做完了。
```

期望结果：不能直接视为完成；应要求用户补充交付物、完成内容和验收证据，或判为 `revise`。

## E05：计划外的求职材料

先用 P01 创建计划，再发送：

```text
这是一个新的岗位要求：需要负责 AI 产品从 0 到 1 落地，熟悉 RAG、Agent、工作流，能做用户调研和数据分析。我需要改变当前计划吗？
```

期望结果：系统应说明现有计划与新 JD 的匹配和缺口；不得把它误判为“今天任务完成”。
