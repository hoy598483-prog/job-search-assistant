# Codex 聊天工作台

## 学习笔记本

从扩展弹窗或工作台打开“学习笔记本”，不需要本机服务或Codex连接。
笔记按浏览器本地学习日期分组，支持方向筛选、日期筛选、全文搜索、手动编辑和删除、Markdown导出。
知识点可手动填写日期、标题和内容；也可在工作台选中文字后点击收藏，未选择文字时会确认是否收藏最新Codex回复。收藏不代表已掌握。
已接受七天计划的任务勾选完成后，记录completed_at和completed_on并在笔记本呈现。全部七天完成时同时呈现整份完成计划。取消误标完成会撤回相应自动收集项。
旧计划没有完成日期的显示日期未知，不推断为导入当天。更换计划后，历史计划中的完成记录仍可查看。
手动计划可点击“将已完成的当前计划收集到笔记本”保存当天快照，需本人明确确认完成。
知识笔记存于chrome.storage.local的learningNotebookEntries；任务与整周完成记录从preparationDirections中的weeklyPlan及weeklyPlanHistory派生，按方向、计划ID、任务天数去重。不会上传笔记到模型服务。
本次仅修改扩展前端，无需重建Native Host；在chrome://extensions重新加载扩展，并关闭旧工作台后重新打开。

## 按岗位方向准备

在“准备方向”中新建并命名方向，例如 AI 产品经理、Agent 开发工程师。填写并保存目标岗位。个人背景改为全局共用。
每个方向分别保存采集暂存、收藏文本、聊天记录、手动选定的项目、计划与进度。新建方向不会复制原方向资料。
弹窗采集文本时归入最近选中的方向；要改变归属，先在工作台切换方向，再采集。
聊天发送前会带入该方向已保存的目标、项目、计划和进度，以及本人确认的全局背景摘要；样本文本需另外勾选。可取消“使用全局背景”复选框；这不会从已有对话中抹除历史引用。每次发送仍需确认。
生成期间不能切换方向。采集区、分析结果和旧版计划显示在切换后清空并重新读取当前方向数据。
旧版单一分区收藏与对话保留在默认 AI 产品求职方向，不会复制到新方向。
在“我的项目与计划”手动保存确认采用的计划及进度；这是自由文本记录，不会自动采纳模型建议或自动审批成果。
所有浏览器本地数据在删除扩展时会清除。

1. 在 Chrome 扩展工作台点击“连接本机 Codex”，同意本次连接并检查官方 CLI 登录。
2. 未登录时点击“启动 Codex 官方登录”，完成后重新检查。桥接、已登录和真实调用成功分别显示。
3. 收藏文本到浏览器本地；在聊天区刷新样本并勾选需要带入的内容。
4. 输入消息，或点击“根据样本生成项目备选”。确认后发送本条消息、最近对话和所选样本。
5. 在对话中选择项目、要求修改方案或生成七天草案。候选不会自动成为已采用计划。

用户明确选择主项目后，Codex直接生成完整七天草案（包含每日任务、时间建议、产出和验收）。
扩展解析并校验隐藏的week_plan数据，仅展示为待确认草案。点击“接受并导入计划”或输入“确认采用计划”后，导入下方Codex一周计划，保存到当前方向的weeklyPlan；旧记录保留在weeklyPlanHistory。
点击“不接受，提出修改”可输入要求并交给Codex重新生成；草案拒绝不会改动当前已接受计划。
每日完成状态由本人勾选，不视作自动验收。草案、已接受计划和进度按方向隔离；格式无效的模型输出不会导入。

Harness 负责工作分区、上下文选择、发送审批、最近20条消息、大小预算、110秒CLI超时和失败反馈。
样本作为不可信网页数据传入；CLI 使用已有官方登录、临时空目录、只读沙箱并关闭工具功能。
聊天使用官方 `codex app-server` stdio 协议，接收 `item/agentMessage/delta` 真实增量，通过带口令的本机 NDJSON 流显示。支持停止生成；取消或断开时清理CLI进程，未完成回复不进入历史。不是嵌入官方 VS Code UI，不支持工具操作或 CLI 原生 session resume。
对话和样本存于 chrome.storage.local，删除扩展会清除数据。服务审计日志不写入文本、对话或口令。
旧版模板计划仅保留历史入口；新的Codex七天计划使用扩展本地状态，不写入旧模板状态机。

## 全局个人背景

个人背景是独立的background.html页面，可从扩展弹窗直接打开，无需建立或选择岗位方向，也不读取activeDirection。Codex连接在此页面单独建立。
用户本人粘贴自述或上传简历（UTF-8 TXT、Markdown、PDF、DOCX，最大2MB）。
PDF最多10页，本地用PDFium渲染原始页面图片，通过官方App Server的localImage输入交给Codex识读。不发送乱码文字层，也支持扫描页面；识读准确度需本人核对，不支持加密文件。
TXT、Markdown、DOCX先展示可编辑原文；随后单独确认发送给Codex。Codex区分原文事实、推断和未知，并省略联系方式。
生成的背景摘要是草案，经本人核对、修改并确认后，存入chrome.storage.local的globalPersonalBackground，所有方向共用。
原始PDF仅保留在页面内存中；渲染图片保存在临时目录，分析结束或失败后清除，不写入长期存储。图片包含原始页面全部信息，发送前需要明确确认。摘要草案存入globalBackgroundDraft，可清除。
清除全局背景不会删除此前对话和计划中的引用；若要删除历史副本，应另外清除对应方向的对话和计划。
旧版各方向background字段仍保留但不再注入模型；如需沿用，请自行复制到原文区重新分析确认。
本地Python直接运行需安装companion/requirements.txt；宿主打包使用--paths work/companion_vendor以包含pypdf和pypdfium2。

Native Host 新构建为 browser_companion/job_companion_native_host_v9.exe，安装脚本注册该文件。
更新后在 chrome://extensions 重新加载扩展并关闭旧工作台；首次安装需运行 install_native_host.ps1 并提供当前扩展ID。
