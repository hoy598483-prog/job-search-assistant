# 原型 v0.1

## 已实现

以已审阅招聘样本为输入，为每项要求关联用户证据状态，保留来源原文，展示加分项，按项目预算生成当天任务。20 分钟预算缩小到一条分析记录，而非压缩完整任务。

首次报告仅选择两个 AI 产品样本，避免混入算法、CAD 和 C++ 要求。用户使用 Codex 和提出产品取舍记录为初步证据，不据此宣布熟练或能力达标。

## 实现原理

聊天负责自然语言理解与资料核实；本地 JSON 保存资料；已审阅映射连接要求与证据；Python 负责预算、输出和来源一致性。这种分工将本轮可验证的规则与尚未接入的自动推理分开。

## 明确未完成

独立模型调用、任意招聘文本自动提取、网页采集、独立聊天界面、自动评价成果、计划版本确认与历史存储、三项有充分证据的相近岗位推荐。

更新：计划版本确认与历史存储已通过 session.py 实现，成果提交和聊天助手审阅也可持久化。其余上述能力仍未实现。计划调整目前支持预算变化，任务内容仍来自模板，不是自动适应所有成果的规划算法。

目前仅生成首次报告，固定任务模板不是完整的长期个性化学习算法。不把当前输出宣传为完整 Agent。

## 下一步

把招聘提取和能力分析接入模型，并继续使用现有测试约束输出；采用何种服务前检查可用运行环境和接入方式，不要求用户在聊天中粘贴密钥。

## 新招聘提取接口进度

extract_job.py 已提供 Responses API 适配、严格结构请求、本地字段校验、连续原文位置校验、部分条件冲突校验和离线候选导入。模型提取结果独立保存为待语义审阅状态，尚未自动接入能力匹配与计划生成。

当前环境没有 OPENAI_API_KEY 或 OPENAI_MODEL，未进行真实API调用。测试与演示均为离线，不代表模型质量评估完成。
