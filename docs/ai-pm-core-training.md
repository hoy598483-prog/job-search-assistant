# AI 产品经理基础知识与项目训练

本训练面向当前目标：AI 产品为主投方向，使用“证据型求职准备 Agent”形成第一份可展示项目。它不要求先学完全部机器学习或所有 Agent 框架。

## 必备知识

| 能力域 | 应理解到什么程度 | 在当前项目中的训练成果 |
| --- | --- | --- |
| 产品问题定义 | 能说清目标用户、场景、痛点、替代方案、首版边界与成功标准 | 为什么求职者不应手工比较多条 JD；首版不做自动投递或录用概率预测 |
| 用户研究与需求判断 | 能将用户反馈、招聘信息和经验资料分开；将观察转成可验证假设 | 资料可信度规则；“聊天录入而非手改 JSON”这一真实产品改动 |
| 大模型基础 | 理解输入、上下文、输出、随机性、幻觉、延迟和成本；知道它不是数据库或规则引擎 | 招聘文本提取只输出结构化候选；原文引用与规则校验在模型外执行 |
| RAG 与检索 | 理解“先找资料再回答”、切分、召回、引用、未命中；能判断何时不需要 RAG | 当前小量 JD 直接处理；未来多条职位或官方资料库才考虑检索 |
| Agent 与工作流 | 能区分固定流程和模型自主决定；定义工具、状态、停止条件和人工确认点 | 岗位输入→提取→审阅→类别能力地图→计划→成果反馈；用户确认后才采用新计划 |
| AI 交互设计 | 让用户理解系统依据、可修改之处、失败原因和下一步；不要求用户替系统做内部操作 | 展示原文、能力状态、任务验收；资料通过聊天输入 |
| 评测与迭代 | 用真实和边界样本测试；区分程序通过、模型质量和产品价值 | 优先/必需、择一条件、注入文本、非招聘文本等测试集；记录失败与修复 |
| 技术协作 | 能读懂数据结构、API 输入输出、状态与测试；能和工程师讨论约束和取舍 | Python 原型、JSON 数据、测试文件、结构化输出接口；无需独自写完全部代码 |
| 业务与领域理解 | 选择一个场景深入，而非泛泛了解所有行业；理解用户成本与结果价值 | AI 求职准备场景；企业协作/知识管理作为后续可验证分支 |

## 一周训练节奏

每天两小时，推荐采用 **20 分钟阅读或拆解参考 → 80 分钟推进一个可演示成果 → 20 分钟审阅和记录**。AI 编写与解释代码；用户负责产品取舍、查看结果、指出不符合真实体验的地方。

| 天数 | 训练主题 | 当前项目动作 | 当天可展示成果 |
| --- | --- | --- | --- |
| 1 | 问题定义与范围 | 写清岗位类别用户、核心痛点、首版不做什么 | 一页问题定义与成功标准 |
| 2 | LLM、结构化输出与边界 | 对一条 JD 提取职责/要求/加分项，保留原文引用 | 提取结果和一条错误案例 |
| 3 | 工作流与 Agent 状态 | 画出输入、提取、审阅、能力地图、计划、反馈的状态变化 | 工作流图和人工确认点 |
| 4 | 用户体验与能力差距 | 将 2–5 条 AI 产品 JD 聚合为 core/targeted/watch/optional | 类别能力地图和优先级理由 |
| 5 | 项目规划与基础补足 | 提供三个项目选项，选择一个，生成最小里程碑 | 项目卡、两小时任务、验收方法 |
| 6 | 评测与迭代 | 运行边界测试，检查是否错误提升“优先项”或虚构引用 | 测试记录、一个修复前后对比 |
| 7 | 产品表达与复盘 | 用新输入完成端到端演示，整理取舍和限制 | 3 分钟演示脚本、项目说明、简历草稿 |

## 按卡点补基础

不预先安排大而全的课程。出现下列阻塞时，插入最小学习任务后立刻返回项目：

| 卡点 | 需补的最小知识 | 回到项目的动作 |
| --- | --- | --- |
| 不理解模型为什么会“看似合理但错误” | 幻觉、提示词约束、结构化输出与外部校验 | 增加一个引用不在原文的失败测试 |
| 不知道 RAG 是否值得加入 | 上下文窗口、检索、引用与未命中 | 比较“少量 JD 直接处理”与“多资料检索”的输入规模和来源需求 |
| 不知道 Agent 是否必要 | 工作流、状态、工具调用、停止条件 | 标出哪些步骤固定，哪些步骤必须由用户确认或模型判断 |
| 不知道如何评价功能 | 测试集、通过条件、人工审阅 | 为一个错误类型添加用例和预期结果 |
| 无法解释工程实现 | API、JSON、数据流、持久化、测试 | 用项目中的一个输入跟踪到最终报告并写出简图 |

## 学习完成标准

完成不等于记住术语，而是能基于自己的项目回答：

1. 这个用户为什么需要它，原本如何解决问题？
2. 哪些环节适合规则，哪些环节使用模型，为什么？
3. 如何防止模型把招聘原文没有写的内容当成事实？
4. 如何知道计划真的帮助用户推进项目？
5. 如果明天增加十条 JD、一个新资料来源或一个失败案例，你会修改哪个环节？

这些问题用于项目复盘和面试叙事，不需要脱离项目做术语考试。
